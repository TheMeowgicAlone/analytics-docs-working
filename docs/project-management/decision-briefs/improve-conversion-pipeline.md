# Improve Conversion Pipeline

- **Owner:** Director
- **Cadence:** Quarterly
- **Decision:** Do we need to improve our conversion pipeline?

## Options / Actions
- A0: Increase monitoring rigor.
- A1: Revamp promotion methods. 

## Success Definition
- The director can monitor the conversion, retention, etc of members.
- Members are automatically categorized into cohorts based behavior.

## Guardrails
- Event attendance is not considered.
- Message behavior should only be considered if cost-effective.
- People in call alone should not be considered.
- Bot messages should be ignored.

## Input Information (Suggested)
- Messages sent daily.
- Average people present in the same all (if cost effective).
- Time spent in voice channels (presence duration).
- Time spent in official event channels (if necessary/appropriate, could be used to accurately guess at event participation, with false positives but zero false negatives).
- role information (will be added if needed)

## Outputs
- KPI: New Member Retention Rate (% of New Members which remain in the server after 2 weeks)
- KPI: Club Member Retention Rate (% of Club Members who remain active)
- KPI: Contributor Retention Rate (% of contributors who remain contributors... e.g continue boosting the server). 
- KPI: Club Member Conversion Rate (% of New Members which convert to Club Members monthly.)
- KPI: Date of Latest Club Member promotion (days since the last member was converted).
- KPI: Contributor Conversion Rate (% of members to become a Contributor monthly). ( provisional )
- KPI: Benefactor Conversion Rate (% of members to become staff/benefactor monthly). ( provisional )
- KPI: Bounce Rate (% of New Members who immediately go inactive, never messaging/etc)
- KPI: Return Rate (% of previously inactive members who became active). ( provisional )

## Important Notes
- Contributor & Benefactor conversion rates may need to be quarterly
- Since promotions are done in batches, date of last Club Member promotion is required to assess freshness.
- Some of this data just can't exist yet, work will need to be done to retroactively construct promotion logs.
- These statistics are extremely well studied, established, etc already. Existing examples should be found and adapted.
